# Node advisories accepted with a reason and a revisit condition.
#
# One `GHSA-…` per line, followed by why it is accepted. Anything not listed
# here fails `just audit`. This file is the reason `pnpm audit --audit-level`
# is NOT lowered: a whole severity class going quiet would hide advisories
# nobody has read.

GHSA-pfhg-q3qv-9q6r
    SvelteKit <3.0.0 — enhanced forms on routes accepting double-slash paths
    can navigate to an external origin (low severity).
    https://github.com/sveltejs/kit/security/advisories/GHSA-pfhg-q3qv-9q6r

    Why accepted temporarily: the only @sveltejs/kit dependency is the
    undeployed E14 benchmark baseline, pinned to 2.70.4 under ADR-0120 for a
    controlled agent comparison. It uses use:enhance with named ?/add and
    ?/clear actions on /stores/[storeId], not a catch-all route accepting
    double-slash paths. This allowance does not establish that 2.70.4 is safe
    for general use or permit exposing the benchmark to untrusted traffic.

    Revisit: when E14-E chooses baseline versions, before exposing the
    baseline outside the local harness, or if a catch-all/enhanced action is
    introduced. Upgrade SvelteKit and its adapter to compatible 3.x releases
    and rerun the three-store contract; remove this allowance on migration.

GHSA-27mw-82g8-phjj
    SvelteKit <3.0.0 — untrusted cache-control passed to setHeaders while
    prerendering can inject markup into the generated page (low severity).
    https://github.com/sveltejs/kit/security/advisories/GHSA-27mw-82g8-phjj

    Why accepted temporarily: the same undeployed, locally exercised E14
    baseline has no prerender setting and does not call setHeaders or forward
    a request-supplied cache-control value. Its only configured adapter is
    adapter-node for the benchmark contract. This exception is not a claim
    that all SvelteKit 2.x applications are unaffected.

    Revisit: at E14-E, before deploying or exposing this baseline externally,
    or if prerendering/setHeaders is introduced. Upgrade to compatible
    SvelteKit >=3.0.0, rerun the contract and remove this allowance.

GHSA-3r8g-jcqq-3p5j
    SvelteKit 2.42.0 to 3.1.0 — a specially crafted request blocks the event
    loop while form data from a remote function (`form`, `query` or
    `command`) is parsed (high; published 2026-11-16).
    https://github.com/advisories/GHSA-3r8g-jcqq-3p5j

    Why accepted temporarily: it affects only an application that enables
    SvelteKit's experimental remote functions. The only @sveltejs/kit
    dependency is the undeployed E14 benchmark baseline, pinned to 2.70.4
    under ADR-0120. Its `svelte.config.js` is `kit: { adapter: adapter() }`,
    with no `experimental.remoteFunctions`. It has no `*.remote.*` module and
    imports nothing from `$app/server`, so no remote function is parsed.
    Untrusted traffic never reaches the local harness.

    Revisit: the advisory lists no patched 2.x release, only 3.1.1, which is
    outside ADR-0120's pin. Remove this allowance once a 2.x patch exists (or
    the baseline moves to 3.x, an ADR of its own) and is installed, a patch
    under the owner's standing approval (2026-11-17). Revisit sooner if the
    baseline enables remote functions or is exposed outside the local harness.

GHSA-6cf5-gc4q-fm3x
    SvelteKit 2.60.1 to 3.1.0 — private (non-exported) `query.batch`
    functions can share a batch, so one function is given another's
    arguments (moderate; published 2026-11-16).
    https://github.com/advisories/GHSA-6cf5-gc4q-fm3x

    Why accepted temporarily: it affects only an application that enables
    the experimental remote functions and declares non-exported
    `query.batch` functions. The undeployed E14 baseline (2.70.4, ADR-0120)
    enables neither and has no remote function at all, as above.

    Revisit: as GHSA-3r8g-jcqq-3p5j. No 2.x release is patched, only 3.1.1.
    Revisit sooner if the baseline enables remote functions.
