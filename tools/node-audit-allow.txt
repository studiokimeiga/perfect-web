# Node advisories accepted with a reason and a revisit condition.
#
# One `GHSA-…` per line, followed by why it is accepted. Anything not listed
# here fails `just audit`. This file is the reason `pnpm audit --audit-level`
# is NOT lowered: a whole severity class going quiet would hide advisories
# nobody has read.

GHSA-g7r4-m6w7-qqqr
    esbuild <0.28.1 — the development server responds to any origin, so a page
    a developer visits while `vite dev` is running can read its responses.

    Why it cannot be fixed here: esbuild reaches this repository only through
    `spikes/marko-stream-resume` -> `@marko/run@0.11.8` ->
    `esbuild-plugin-browserslist@2.0.0`, whose peer range is `~0.27.0`. A
    tilde range does not admit 0.28.x, so moving esbuild means moving the
    `@marko/run` pin — and that pin is what E0's resumption and payload
    measurements were taken against. A pnpm override was tried on 2026-08-06
    and does not take, for this reason.

    Why the residual risk is acceptable: the exposure is the *dev server*.
    Nothing in this repository runs `vite dev`; the spike runs
    `marko-run build` and serves the built output, and `just ci` does not
    invoke Vite at all. No production artifact contains esbuild.

    Revisit: when `@marko/run` releases a version depending on
    `esbuild-plugin-browserslist` with an `^0.28` range, or when ADR-0002's
    deletion condition retires Marko at E7.

GHSA-vfj7-8cjw-p6xm
    braces <=3.0.3 — a deeply nested brace pattern exhausts the stack (a
    denial of service). No release is patched: 3.0.3 is the latest, and the
    advisory lists no fixed version (checked 2026-10-07, ADR-0244).

    Why it cannot be fixed here: braces reaches this repository only through
    `spikes/marko-stream-resume` -> `@marko/run@0.11.8` -> `@marko/vite` ->
    `fast-glob` -> `micromatch`, the build's file globbing.

    Why the residual risk is acceptable: the patterns it expands are the
    spike's own build globs, never input from a request, and no production
    artifact contains it.

    Revisit: when braces publishes a fixed release, when `@marko/vite` stops
    depending on micromatch, or when ADR-0002's deletion condition retires
    Marko at E7.

GHSA-pfhg-q3qv-9q6r
    SvelteKit <3.0.0 — enhanced forms on routes accepting double-slash paths
    can navigate to an external origin (low severity).
    https://github.com/sveltejs/kit/security/advisories/GHSA-pfhg-q3qv-9q6r

    Why accepted temporarily: the only @sveltejs/kit dependency is the
    undeployed E14 benchmark baseline, pinned to 2.70.3 under ADR-0120 for a
    controlled agent comparison. It uses use:enhance with named ?/add and
    ?/clear actions on /stores/[storeId], not a catch-all route accepting
    double-slash paths. This allowance does not establish that 2.70.3 is safe
    for general use or permit exposing the benchmark to untrusted traffic.

    Revisit: when E14-E chooses baseline versions, before exposing the
    baseline outside the local harness, or if a catch-all/enhanced action is
    introduced. Upgrade SvelteKit and its adapter to compatible 3.x releases
    and rerun the three-store contract; remove this allowance on migration.

GHSA-27mw-82g8-phjj
    SvelteKit <3.0.0 — untrusted cache-control passed to setHeaders while
    prerendering can inject markup into the generated page (low severity).
    https://github.com/sveltejs/kit/security/advisories/GHSA-27mw-82g8-phjj

    Why accepted temporarily: the same undeployed, locally exercised E14
    baseline has no prerender setting and does not call setHeaders or forward
    a request-supplied cache-control value. Its only configured adapter is
    adapter-node for the benchmark contract. This exception is not a claim
    that all SvelteKit 2.x applications are unaffected.

    Revisit: at E14-E, before deploying or exposing this baseline externally,
    or if prerendering/setHeaders is introduced. Upgrade to compatible
    SvelteKit >=3.0.0, rerun the contract and remove this allowance.

GHSA-mw6w-2fmv-pvw3
    SvelteKit <2.70.4 (and 3.0.0 to 3.1.0) — where `reroute` turns an invalid
    percent-encoded path into a valid one, a comparison can crash an
    adapter-node server (moderate; published 2026-11-13).
    https://github.com/advisories/GHSA-mw6w-2fmv-pvw3

    Why accepted temporarily: the only @sveltejs/kit dependency is the
    undeployed E14 benchmark baseline, pinned to 2.70.3 under ADR-0120. It
    declares no `reroute` hook (it has no `src/hooks.ts`; its server hook is
    `handle` alone), so the comparison the advisory names is never made. The
    baseline is a local harness that untrusted traffic never reaches.

    Revisit: a patched release exists, 2.70.4, a patch within ADR-0120's pin.
    Move to it once the owner approves the download (2026-11-16, asked), rerun
    the three-store contract and remove this allowance; sooner if `reroute`
    is introduced or the baseline is exposed outside the local harness.

GHSA-rqw3-x7hx-mm3p
    @sveltejs/adapter-node 5.5.7 (and 6.0.0-next to 6.0.0) — the adapter can
    add a header to an immutable request where a request is proxied through
    `fetch`, which crashes the server for every request it serves (moderate;
    published 2026-11-13).
    https://github.com/advisories/GHSA-rqw3-x7hx-mm3p

    Why accepted temporarily: the same undeployed E14 baseline, pinned to
    adapter-node 5.5.7 under ADR-0120, makes no `fetch` from its server code
    (`src/hooks.server.ts`, `src/lib/server/`, its one `+page.server.ts`), so
    it proxies no request, and no untrusted client reaches it.

    Revisit: a patched release exists, 5.5.8. Move to it with SvelteKit 2.70.4
    on the owner's approval of the download, rerun the three-store contract and
    remove this allowance; sooner if the baseline proxies a request or is
    exposed outside the local harness.

GHSA-3r8g-jcqq-3p5j
    SvelteKit 2.42.0 to 3.1.0 — a specially crafted request blocks the event
    loop while form data from a remote function (`form`, `query` or
    `command`) is parsed (high; published 2026-11-16).
    https://github.com/advisories/GHSA-3r8g-jcqq-3p5j

    Why accepted temporarily: it affects only an application that enables
    SvelteKit's experimental remote functions. The only @sveltejs/kit
    dependency is the undeployed E14 benchmark baseline, pinned to 2.70.3
    under ADR-0120. Its `svelte.config.js` is `kit: { adapter: adapter() }`,
    with no `experimental.remoteFunctions`. It has no `*.remote.*` module and
    imports nothing from `$app/server`, so no remote function is parsed.
    Untrusted traffic never reaches the local harness.

    Revisit: the advisory lists no patched 2.x release, only 3.1.1, which is
    outside ADR-0120's pin. Remove this allowance once a 2.x patch exists (or
    the baseline moves to 3.x, an ADR of its own) and is installed on the
    owner's approval of the download. Revisit sooner if the baseline enables
    remote functions or is exposed outside the local harness.

GHSA-6cf5-gc4q-fm3x
    SvelteKit 2.60.1 to 3.1.0 — private (non-exported) `query.batch`
    functions can share a batch, so one function is given another's
    arguments (moderate; published 2026-11-16).
    https://github.com/advisories/GHSA-6cf5-gc4q-fm3x

    Why accepted temporarily: it affects only an application that enables
    the experimental remote functions and declares non-exported
    `query.batch` functions. The undeployed E14 baseline (2.70.3, ADR-0120)
    enables neither and has no remote function at all, as above.

    Revisit: as GHSA-3r8g-jcqq-3p5j. No 2.x release is patched, only 3.1.1.
    Revisit sooner if the baseline enables remote functions.

GHSA-rqp5-r3wg-vg35
    SvelteKit <2.70.4 (and 3.0.0 to 3.1.0) — where `router.resolution` is
    `'server'`, a crafted link followed by client-side navigation can import
    and run a module from another origin (moderate; published 2026-11-16).
    https://github.com/advisories/GHSA-rqp5-r3wg-vg35

    Why accepted temporarily: it affects only an application with
    `router.resolution: 'server'`. The undeployed E14 baseline (2.70.3,
    ADR-0120) sets no `router` option, so it resolves routes in the browser,
    the default, and no user browses it outside the local harness.

    Revisit: a patched release exists, 2.70.4, the patch within ADR-0120's pin
    that GHSA-mw6w-2fmv-pvw3 already waits on. Move to it once the owner
    approves the download (asked 2026-11-16), rerun the three-store contract
    and remove this allowance. Revisit sooner if the baseline sets
    `router.resolution: 'server'`.

GHSA-mfr8-8qww-v76h
    Next.js 16.3.0 to 16.4.4 — a `'use cache'` function that reads a root
    param, called both directly while rendering and through
    `unstable_cache()`, can be given another root param value's cached data,
    through a deduplication race at a cold process start (moderate;
    published 2026-11-16, CVE-2026-119790).
    https://github.com/advisories/GHSA-mfr8-8qww-v76h

    Why accepted temporarily: the only `next` dependency is the undeployed
    E14 benchmark baseline, `benchmarks/baselines/next-react`, pinned to
    16.4.1 under ADR-0120 (amended 2026-10-22). It declares no `'use cache'`
    function, calls no `unstable_cache()` and has no root params: its one
    layout, `app/layout.tsx`, takes no parameter, its `next.config.mjs` is
    empty, and its only `next/cache` import is `revalidatePath`. Outside the
    race the nesting throws (`'use cache' inside unstable_cache() is
    unsupported`), and the advisory calls avoiding it a complete workaround.
    Untrusted traffic never reaches the local harness.

    Revisit: a patched release exists, 16.4.5. Move to it on the owner's
    approval of the download, rerun the three-store contract
    (`e14-contract`) and remove this allowance; sooner if the baseline
    declares a `'use cache'` function, calls `unstable_cache()` or gives its
    root layout a parameter.
