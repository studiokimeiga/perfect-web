# Linux ARM64 CI: target-specific LLD

Scope: ARM64 GitHub Actions Cargo compilation only. The x64 and Wasm
toolchains and all tests remain unchanged. This is not an app-runtime speed
claim, nor proof that all CI wall time is halved.

## Measured candidate

Rust 1.97.1, Ubuntu 24.04 ARM64, same three packages, three successful clean
Cargo target builds per candidate, counterbalanced on one runner:

| Linker | Median clean compile (seconds) |
|---|---:|
| Existing system default | 130.745 |
| Ubuntu LLD 18.1.3 | 64.086 |
| mold 2.30.0 | 74.296 |

LLD was 51.0% faster than the ARM system default and 13.7% faster than
mold in that workload. All three built programs passed the adapter smoke.
On Linux x64, explicit LLD was essentially tied with the default and mold
was slower, both with and without debug info, so x64 is unchanged.

Evidence: https://github.com/studiokimeiga/perfect-web/actions/runs/40122533439
and https://github.com/studiokimeiga/perfect-web/actions/runs/40122916735

## Integration strategy

The Ubuntu ARM64 package is pinned to lld version 1:18.0-59~exp2,
which supplies Ubuntu LLD 18.1.3. The setup script refuses a different
version or missing package; it does not silently fall back.

Cargo gets its linker from the ARM target-specific environment variable,
not from global RUSTFLAGS. Two self-contained Cargo builds prove actual linker invocation and execution:
one with an explicit ARM64 target and **one without `--target`**, matching
production `just ci` / `cargo test`. The invocation log is reset between
probes; explicit-target success cannot disguise a missing native setting. Different cache keys
avoid accepting binaries previously linked by the system default.

Native Cargo unit, integration and doctest shards are unchanged, as are the
compiler, Koka, audit, and verification gates. A PR may merge only after
all required x64 and ARM jobs and the affected verification and security
checks pass for the exact candidate. Compare overall CI wall time after
merging; apt installation time, cache warming and runner scheduling can
change the realized benefit.
